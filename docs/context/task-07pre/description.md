Чему учимся
Это продолжение проекта «Календарь звонков»: приложение уже написано, и здесь мы переносим работу с агентом из локальной разработки в GitHub-процесс команды. Агент перестаёт быть помощником в терминале одного человека и становится участником процесса: отвечает в issue, разбирает задачу, открывает pull request, вносит правки после ревью и выходит по расписанию с регулярной проверкой.

Устроено это через GitHub App и воркфлоу в .github/workflows/. Событие в репозитории (комментарий, открытие pull request, срабатывание расписания) запускает агента внутри GitHub Actions, а результат появляется там же, где идёт работа команды. Шаги проекта идут по этим сценариям по очереди, и каждый называет, что должно остаться в репозитории после него.

Проверяется в этом проекте процесс. Продуктовая функциональность не растёт, зато остаются следы работы, которые открываются глазами: прогоны в Actions, ответы агента в issue, pull request с правками после ревью, сохранённый отчёт регулярной проверки.

Описание проекта
Репозиторий предыдущего проекта берётся целиком: приложение, тесты, линтеры, прогон в GitHub Actions, release-please и AGENTS.md. Всё это остаётся рабочим и используется дальше. Агент в GitHub Actions читает тот же AGENTS.md, а коммиты по Conventional Commits так же собираются в release-PR.

Каждый проект на Хекслете выполняется в своём репозитории, поэтому первым делом код переносится в новый. Заодно нужен небольшой план развития: одна-две фичи и один-два бага. Дальше по шагам агент разбирает именно эти задачи, поэтому они должны быть похожи на настоящие: сформулированные как жалоба пользователя, без готового решения внутри.

Требования
Код приложения из предыдущего проекта лежит в новом репозитории, автоматическая проверка на нём зелёная.
Есть план развития приложения: минимум одна фича и один баг, каждый пункт понятен без пересказа.
Задачи
Создайте новый репозиторий и перенесите в него код приложения из проекта «Календарь звонков» вместе с Dockerfile, тестами, линтерами и воркфлоу.
Убедитесь, что автоматическая проверка проекта в новом репозитории зелёная.
Составьте план развития: выпишите фичи и баги, которые дальше будет разбирать агент.
Результат шага
В новом репозитории лежит рабочее приложение из предыдущего проекта, и есть план развития, по которому идёт дальнейшая работа с агентом.
