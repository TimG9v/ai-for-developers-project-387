## Цель

`/to-tickets` публикует вертикальные тикеты (tracer bullets) с нативными
блокировками в GitHub Issues (метка `ready-for-agent`) — требование
`descripton.md` № 3: «тикеты с объявленными зависимостями». После шага — приёмка
задачи.

## Предусловия

1. Шаг 7 выполнен: issue-спецификация существует (номер известен).
2. `make generate` зелёный (тикеты будут опираться на готовый pipeline).
3. Сессия видит спеку и код (скилл сам fetched issue по аргументу).

## Действия

1. Пользователь запускает `/to-tickets <номер спеки>`; скилл читает issue и
   комментарии.
2. Агент предлагает вертикальную раскладку: каждый тикет — узкий, но полный путь
   через слои (контракт → сервер → интерфейс → тесты), сам по себе проверяем и
   влезает в одну свежую сессию. Контракт и pipeline уже готовы шагами 3–6 —
   тикеты их потребляют, а не воспроизводят.
3. Квиз пользователя (скилл): гранулярность, корректность блокировок, склейка/
   разрезание. Итерировать до одобрения — раскладку публикует только после «да».
4. Публикация в порядке зависимостей (блокеры первыми), по одному issue на тикет,
   нативные блокировки (API `blocked_by`, database id), метка `ready-for-agent`,
   секция Parent — ссылка на спеку. Каждому тикету — критерии приёмки.
5. Parent-спеку и карту не закрывать и не менять.

## Ожидаемая форма раскладки (рекомендация; финал — квиз скилла)

| # | Тикет (суть)                                             | Блокируется |
| - | -------------------------------------------------------- | ----------- |
| 1 | Список типов встреч: сервер + страница гостя + тесты     | —           |
| 2 | Владелец: создание типа встречи (форма + POST + тесты)   | 1           |
| 3 | Календарь слотов гостя: публикация слотов + окно 14 дней | 1           |
| 4 | Запись гостя: форма, POST, 409 на занятый слот           | 3           |
| 5 | Админка: список записей всех типов                       | 4           |

Каждый тикет проходит все слои и завершается `make test` + `make lint`; вертикаль
демо́ится без соседних тикетов.
