## Цель

`/to-spec` публикует в GitHub Issues спецификацию приложения (метка
`ready-for-agent`): пользовательские истории, принятые решения реализации и
решения по тестированию — требование `descripton.md` № 2. Спецификация
синтезируется из карты, интервью скилл не проводит.

## Предусловия

1. Шаг 2 закрыт: карта разобрана, фронт пуст, ответы в Decisions so far.
2. **Сессия загружает карту**: `descripton.md` требует запускать `/to-spec` в той
   сессии, где карта и ответы по её задачам загружены в контекст. Практика:
   открыть свежую сессию, прочитать карту и все закрытые билеты
   (`gh issue view <map>` + по одному на билет), затем звать скилл.
3. `CONTEXT.md` содержит словарь после шага 2 — спека пишется его словами.

## Действия

1. Пользователь запускает `/to-spec`.
2. Агент по скиллу: без интервью; предложить **швы тестирования** и согласовать
   их с пользователем до записи спеки. Рекомендация швов для этого проекта:
   - backend: HTTP-слой axum (тесты дергают роутер через контрактные типы —
     наивысший шов без БД);
   - frontend: страницы через сгенерированный SDK (мок уровня SDK, не fetch).
   Чем меньше швов, тем лучше; пользователь утверждает.
3. Написать спеку по шаблону скилла, без путей и кода:
   - Problem Statement — запись на звонок не автоматизирована (ракурс владельца
     и гостя);
   - Solution — в двух предложениях, словами словаря;
   - User Stories — длинный нумерованный список: владелец (типы встреч, список
     записей), гость (виды брони, календарь на 14 дней, запись), правила
     (уникальность слота, окно), ошибки (409/404) — по решениям карты;
   - Implementation Decisions — дословно Decisions so far карты (термины, модель
     слота, обязательность гостя, хранение, граница владельца, pipeline
     `make generate`); без имён файлов;
   - Testing Decisions — утверждённые швы + что хороший тест (внешнее поведение)
     + приоритет: контрактные тесты HTTP, тесты страниц;
   - Out of Scope — регистрация/авторизация, БД, i18n, интеграции с календарями
     (из `context/tmp/description.md` и решений карты).
4. Опубликовать:

   ```bash
   gh issue create --label ready-for-agent \
     --title "Спецификация: запись на звонок (бронирование)" \
     --body-file /tmp/opencode/booking-spec.md
   ```

5. Не закрывать карту и не менять её билеты — спека отдельный артефакт.
