## Что сделано

1. `frontend/openapi-ts.config.ts` — конфиг `@hey-api/openapi-ts` 0.99.0:
   вход `../openapi/openapi.yaml`, выход `src/client`. Опция `format: prettier`
   из плана не применена — prettier в проекте нет (plan допускал подгонку
   конфига под версию инструмента).
2. `frontend/package.json` — devDep `@hey-api/openapi-ts`, скрипт
   `generate:client`.
3. `frontend/src/client/**` — сгенерированный SDK: 6 функций из operationId
   (`bookingsList/Create`, `eventTypesList/Create`, `slotsList/Create`),
   типы `Booking`/`EventType`/`Slot` 1:1 с контрактом (русские `@doc` переехали
   в JSDoc), самодостаточный fetch-рантайм — новых runtime-зависимостей не
   потребовалось.
4. `frontend/tests/sdk.test.ts` — проверка «фронтенд может им пользоваться»:
   экспорты-функции + литерал `Booking` по форме контракта. Имена функций в
   тесте — фактические из генерата (план предполагал подгонку).
5. `frontend/eslint.config.mjs` — `src/client/**` в globalIgnores: линтер
   падал на сгенерированном коде (4 × `no-explicit-any` в core/*.gen.ts);
   правило «сгенерированное руками не правится» → генерат не линтуется,
   правится только регенерацией.

## Типобезопасность — где проверяется

vitest транслирует TS без проверки типов, поэтому тип-литерал `Booking` в тесте
проверяется компиляцией `next build` (strict), а не рантаймом теста. Оба прогона
в чек-листе; пара «тест + build» вместе закрывают пункт плана.
