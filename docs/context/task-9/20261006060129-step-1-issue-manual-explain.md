## Действия

- [ ] 1. Создать issue A из «Фичи 1» плана развития (жалоба
  пользователя, без готового решения):

  ```bash
  gh issue create \
    --title "Отмена и перенос записи" \
    --body "$(cat <<'EOF'
  Я записался на звонок и ошибся временем. Отменить или перенести запись
  негде: слот остаётся занятым до самой встречи, а связаться со мной по
  этой записи никто не может. Владельцу остаётся только ждать гостя на
  встречу, который не придёт, и вручную разбираться с памятью сервиса —
  данных о записи после перезапуска и так не остаётся.

  Источник: docs/context/task-7pre/20261005142605-development-plan.md,
  «Фича 1» (жалоба пользователя, без готового решения).
  EOF
  )" \
    --label "enhancement"
  ```

  Ожидание: URL issue (далее номер `A`).

- [ ] 2. Позвать агента командой из описания задачи:

  ```bash
  gh issue comment A --body "/oc explain this issue"
  ```

  Ожидание: комментарий создан; воркфлоу `opencode` стартует
  автоматически (событие `issue_comment`, условие `/oc`).

- [ ] 3. Дождаться завершения прогона (обычно 1–5 минут):

  ```bash
  gh run list --workflow=opencode.yml --limit 1
  sleep 60 && gh run list --workflow=opencode.yml --limit 1
  ```

  Ожидание: `completed` + `success`. Возможные лишние прогоны
  `failure`/`skipped` сразу после успеха — известное самопробуждение
  от ссылки на shared-сессию в ответе бота (наблюдение task-8,
  perm-гейт), не дефект; фиксировать в отчёте.

- [ ] 4. Прочитать разбор и оценить по критериям спеки:

  ```bash
  gh issue view A --comments
  ```

  Чек-лист качества (спека: «назвать причину, затронутые части кода
  и предлагаемый путь исправления»): (1) названа причина/корень;
  (2) названы файлы/модули, не «где-то в backend»; (3) путь
  исправления предложениями, не общими словами. Если пункт не
  освещён — повторный вызов с уточнением:
  `/oc укажи затронутые файлы и путь исправления подробнее`.

- [ ] 5. Если разбор полезный, запросить следующий шаг — план
  исправления (правку `/oc fix this` здесь не берём: спека требует
  постановку, не PR; альтернатива — открытый вопрос 1 плана):

  ```bash
  gh issue comment A --body "/oc propose a fix plan"
  ```

  Ожидание: второй прогон `opencode`; инструкция — весь текст
  комментария рядом с командой (docs Custom prompts/Examples).

- [ ] 6. Дождаться второго прогона и прочитать план:

  ```bash
  sleep 60 && gh run list --workflow=opencode.yml --limit 3
  gh issue view A --comments
  ```

  Ожидание: второй ответ агента — план исправления по шагам.

- [ ] 7. Зафиксировать для шага 3: номер/URL issue A, id и
  длительности обоих прогонов, одну-две цитаты разбора (причина,
  файлы, путь) — материал сравнения и постановки.
