## Цель

Новая issue B автоматически получила разбор агента (триаж-прогон
`success` при создании, комментарий в issue); правка issue не
перезапускает агента; сравнение двух разборов (ручной шаг 1 vs
автотриаж) зафиксировано с выводом «который точнее и почему»; в
issue A записана итоговая постановка «что считается исправлением»;
таблица приёмки всех четырёх требований спеки заполнена
real-run-доказательствами.

## Действия

- [ ] 1. Создать issue B из «Фичи 2» плана развития (жалоба
  пользователя, без готового решения):

  ```bash
  gh issue create \
    --title "Рабочие окна расписания вместо ручных слотов" \
    --body "$(cat <<'EOF'
  Я владелец календаря. Чтобы открыть приём на неделю, я руками публикую
  каждый получасовой слот отдельной формой — это десятки одинаковых
  операций, стоит отвлечься, и в расписании дырки. Хочу один раз задать
  свои рабочие часы («пн–пт, 10:00–17:00 моего времени») и быть уверенным,
  что гость из другого региона видит это время корректно для себя, а не
  догадывается, чей это часовой пояс.

  Источник: docs/context/task-7pre/20261005142605-development-plan.md,
  «Фича 2» (жалоба пользователя, без готового решения).
  EOF
  )" \
    --label "enhancement"
  ```

  Ожидание: URL issue (далее номер `B`). Создание issue — триггер
  `issues: [opened]`: триаж-прогон стартует сам, вызывать агента
  командой не нужно.

- [ ] 2. Дождаться завершения триаж-прогона:

  ```bash
  gh run list --workflow=opencode-triage.yml --limit 1
  sleep 60 && gh run list --workflow=opencode-triage.yml --limit 1
  ```

  Ожидание: ровно один прогон, `completed` + `success`; длительность
  зафиксировать для отчёта.

- [ ] 3. Проверить разбор агента в issue B:

  ```bash

  ```

  Ожидание: комментарий от `opencode-agent[bot]` без команды-вызова
  (инструкция пришла из `prompt` воркфлоу) и со структурой из
  `prompt`: суть / причина + файлы / путь; при нехватке данных —
  уточняющие вопросы в том же комментарии.

- [ ] 4. Проверить самопробуждение коммент-воркфлоу (проверка
  гипотезы `share: false`):

  ```bash
  gh run list --workflow=opencode.yml --limit 3
  ```

  Ожидание при верной гипотезе: новых прогонов нет — счётчик совпадает
  с шагом 1 (два success + возможные старые самопробуждения). Если
  появились `failure`/`skipped` от комментария бота — известный
  паттерн task-8 (perm-гейт, не петля), не дефект триажа: задокументировать
  в отчёте, вопрос отключения share у бота — вне объёма.

- [ ] 5. Отрицательная проверка: правка issue не перезапускает агента:

  ```bash
  BODY=$(gh issue view B --json body --jq .body)
  gh issue edit B --body "${BODY}

  _Тело дополнено строкой для проверки: правка issue не триггерит триаж._"
  sleep 30 && gh run list --workflow=opencode-triage.yml --limit 3
  ```

  Ожидание: число триаж-прогонов не выросло (`types: [opened]`,
  review focus 3). Дописанная строка остаётся в body как след проверки —
  допустимо; при желании убрать той же командой без строки.

- [ ] 6. Сравнить два разбора (задача 5 описания) — заполнить
  таблицу, вердикт каждой строки — real-run чтение тредов:

  ```bash
  gh issue view A --comments
  gh issue view B --comments
  ```

| Критерий сравнения                                   | Ручной `/oc explain` (issue A) | Автотриаж (issue B)    |
| ---------------------------------------------------- | ------------------------------ | ---------------------- |
| Причина/корень названы и верны по коду               | (заполнить по треду A)         | (заполнить по треду B) |
| Конкретика затронутых файлов (имена, не общие слова) |                                |                        |
| Путь исправления: шаги и реалистичность              |                                |                        |
| Учёт контекста: тред целиком / только issue + prompt |                                |                        |
| Вопросы по недостающим данным                        |                                |                        |

  Вывод «который точнее и почему» — одной формулировкой в отчёт.
  Ограничение сравнения зафиксировать: A и B — разные жалобы,
  сравниваются форма и глубина разбора, не совпадение выводов.
  Факторы различия: ручной вызов читает весь тред и инструкцию из
  комментария; автотриаж получает `prompt` из воркфлоу и пишет без
  запроса.

- [ ] 7. Итоговая постановка в issue A (задача 6 описания,
  требование 4) — комментарий «Что считается исправлением».
  Формулирует пользователь из жалобы + разбора + плана шага 1;
  каркас комментария:

  ```bash
  gh issue comment A --body "$(cat <<'EOF'
  ## Что считается исправлением (итоговая постановка)

  **Критерии приёмки** (из жалобы и разбора):
  - <что должно стать возможным для гостя — из жалобы>;
  - <какое поведение исчезает — из жалобы>;
  - <что проверяет владелец руками на деплое>.

  **Затронутые части** (из разбора агента, сверить с кодом):
  - <файлы/модули из ответа агента, поправленные по факту>.

  **Ограничения и out-of-scope**:
  - <например: персистентность хранилища — решение из разбора/плана>;
  - <что сознательно не чиним в этой задаче>.

  **Что НЕ считается исправлением**: <частичные меры, оставляющие
  жалобу актуальной>.
  EOF
  )"
  ```

  Каждый слот заполняется содержанием из треда A (цитаты разбора и
  плана); пустые слоты в отправленный комментарий не попадают.
