## Цель

`/wayfinder` (режим Chart the map) отработал: в GitHub Issues есть карта
«Проектирование бронирования» (метка `wayfinder:map`) с Destination, Notes, пустыми
Decisions so far, туманом в Not yet specified и границей в Out of scope; под ней —
дочерние билеты-вопросы с метками `wayfinder:<type>` и нативными блокировками.
Карта ничего не решает — чартинг только размечает путь.

## Предусловия

1. `gh` установлен и аутентифицирован — проверка (real-run перед стартом):

   ```bash
   gh auth status && gh repo view --json name -q .name
   ```

   Если нет — пользователь ставит `gh` и проходит `gh auth login` (см. открытый
   вопрос 1 общего плана). Без трекера шаг не начинается.
2. Ветка `task-4` (создана), дерево чистое.
3. Прочитаны `descripton.md` (требования и пункт назначения) и `CONTEXT.md`
   (словарь task-3 — он расходится с доменом шага, это корм для билетов).

## Действия

1. Пользователь запускает `/wayfinder` с идеей: «проектирование бронирования:
   типы встреч, календарь свободных слотов, запись, список встреч владельца;
   destination — утверждённая спецификация приложения, по которой раскладываются
   тикеты» (пункт назначения дан в `descripton.md` — не изобретать заново).
2. Агент по скиллу: destination зафиксировать (grilling + domain-modeling), затем
   фронт breadth-first: пройтись по всему пространству решений, не углубляясь.
   Факты из репозитория агент проверяет сам; решения — только от пользователя.
3. Создать карту:

   ```bash
   gh issue create --label wayfinder:map \
     --title "Карта решений: проектирование бронирования" \
     --body-file /tmp/opencode/wayfinder-map-body.md
   ```

   Тело — по шаблону SKILL.md: `## Destination`, `## Notes` (домен, скиллы сессии:
   grilling + domain-modeling, правило «решения — пользователь»), `## Decisions
   so far` (пусто), `## Not yet specified` (туман), `## Out of scope`.
4. Создать стартовые билеты как sub-issues карты (`gh api`, sub-issues endpoint;
   иначе task-list в теле карты + `Part of #<map>` в теле билета). Каждому — метка
   `wayfinder:grilling|research|prototype|task` и тело `## Question`.
5. Назначить блокировки вторым проходом (native dependencies, database id):

   ```bash
   gh api repos/<owner>/<repo>/issues/<child>/dependencies/blocked_by \
     -F issue_id=<blocker-db-id>
   ```

6. Выпустить research-субагентов по research-билетам (параллельно).
7. Стоп: чартинг ровно одна сессия, решений в ней нет.
