## Задача

Шаг 3 «Первая фича: главная страница» (`context/tmp/task-3/descripton.md`): пройти весь
цикл агентной работы целиком на первой фиче — главной странице, которая рассказывает
про сервис и ведёт на страницу записи. Цикл: интервью `/grill-with-docs` (словарь в
`CONTEXT.md` + решения в `docs/adr/`) → реализация `/implement` (код вместе с тестами)
→ зелёный прогон GitHub Actions. Общий контекст проекта — `context/tmp/description.md`
(домен «запись на звонок»: слоты по 30 минут, владелец и гость, без авторизации).

Особенность шага: решений мало, основная работа — интервью. Оно передаёт агенту знание
о проекте один раз и оставляет его в репозитории, чтобы не пересказывать в каждой
новой сессии.

## Механика (real-run 2026-09-29 — чтение SKILL.md и форматов)

- `grill-with-docs` — тонкая обёртка (7 строк SKILL.md): вызывает скиллы `grilling` и
  `domain-modeling`. Флаг `disable-model-invocation: true` — запускать командой
  `/grill-with-docs`, сам агент не вызывает.
- `grilling` — интервью раундами по дереву решений: агент спрашивает весь «фронтир»
  (вопросы, чьи предпосылки уже решены) пачкой, нумерует, даёт рекомендованный ответ,
  ждёт ответов пользователя. Факты из среды ищет сам, у пользователя — только решения.
  Сессия завершена, когда фронтир пуст.
- `domain-modeling` — термины по ходу разговора немедленно пишутся в `CONTEXT.md`
  (формат `## Language`: термин → 1–2 предложения + `_Avoid_:` синонимы; никаких
  деталей реализации). ADR — только при трёх условиях одновременно: трудно обратить,
  удивительно без контекста, реальный trade-off. Формат: `docs/adr/0001-slug.md`,
  заголовок + 1–3 предложения. Каталоги создаются лениво.
- Конвенция доменных документов зафиксирована task-2 в `docs/agents/domain.md`:
  single-context — `CONTEXT.md` в корне + `docs/adr/`.
- `implement` — реализует работу по спеке: `/tdd` где возможно, регулярный typecheck,
  полный прогон тестов в конце, `/code-review`. Инструктирует «Commit your work» —
  противоречит глобальному правилу пользователя (агент git read-only); правила
  пользователя приоритетны, коммиты делает пользователь (перенесено из отчёта task-2).

## Последовательность работ (каждый пункт — отдельный Conventional Commit)

Пользователь создаёт рабочую ветку `task-3` (агент git read-only).

1. `docs:` — шаг 1: `/grill-with-docs` — интервью по главной странице → `CONTEXT.md`
   + `docs/adr/0001-*.md`; проверка форматов и словаря.
   Коммит: `docs: add project glossary and first ADR`.
2. `feat(frontend):` — шаг 2: `/implement` — тесты (обновление smoke + новый booking)
   → код (главная + заглушка `/booking` + metadata) → `make test-frontend`,
   `make lint-frontend`, `npm run build` → `/code-review`.
   Коммит: `feat(frontend): add homepage linking to booking page`.
3. Приёмка — шаг 3 без коммита кода: пуш и PR (пользователь) → зелёный GitHub
   Actions → чек-лист четырёх требований; контекст-отчёт о приёмке
   (`docs: add task-3 acceptance report` — опционально, как в task-2).
