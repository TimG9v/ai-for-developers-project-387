Интервью `/grill-with-docs` пройдено: в корне репозитория появился `CONTEXT.md` со
словарём проекта, в `docs/adr/` — первое принятое решение. Вопросы фронтира решены,

## Действия

1. Пользователь создаёт рабочую ветку и запускает интервью в сессии OpenCode в корне
   репозитория:

   ```bash
   git checkout -b task-3
   ```

   затем команда `/grill-with-docs` с темой: «главная страница приложения — что на ней
   находится и как она ведёт на страницу записи».

2. Интервью идёт раундами (скилл `grilling`): агент задаёт вопросы фронтира пачкой,
   нумерует их и прикладывает свой рекомендованный ответ; пользователь отвечает —
   решения за ним. Факты о репозитории агент проверяет сам. Следующий раунд — по
   вопросам, которые открылись ответами.
3. Ожидаемый фронтир первого раунда — таблица (рекомендации плана; решения принимает
   пользователь, при расхождении выигрывает интервью):

| # | Вопрос               | Рекомендация плана                                                        | Артефакт   |
| - | -------------------- | ------------------------------------------------------------------------- | ---------- |
| 1 | Язык интерфейса      | русский; тексты скаффолда заменить; i18n вне объёма проекта               | ADR `0001` |
| 2 | Имя целевой страницы | «страница записи»; avoid: «страница бронирования»                         | CONTEXT.md |
| 3 | Маршрут              | `/booking`, латиница, kebab-case                                          | разговор   |
| 4 | Целевой страницы нет | заглушка `/booking` в этом шаге: без цели требование «ведёт» нетестируемо | шаг 2      |
| 5 | Содержимое главной   | заголовок + 1–2 предложения о сервисе + CTA-кнопка-ссылка                 | шаг 2      |
| 6 | Словарь домена       | термины из списка ниже                                                    | CONTEXT.md |

4. Кандидаты в словарь (формулировки финализирует интервью; формат — термин +
   1–2 предложения «что это», `_Avoid_` — синонимы):

   - **Главная страница** — входная точка приложения: рассказывает про сервис и ведёт
     на страницу записи. _Avoid_: лендинг.
   - **Страница записи** — страница, где гость выбирает слот и оформляет запись.
     _Avoid_: страница бронирования, каталог встреч.
   - **Слот** — свободный 30-минутный интервал, опубликованный владельцем.
   - **Запись** — слот, закреплённый за гостем; результат выбора на странице записи.
     _Avoid_: бронь, резервация.
   - **Встреча** — записанный звонок в списке владельца. _Avoid_: событие.
   - **Владелец календаря** — тот, кто публикует слоты. _Avoid_: админ, пользователь.
   - **Гость** — тот, кто выбирает слот и записывается. _Avoid_: клиент, посетитель.

   Правило словаря: только термины домена; маршруты, компоненты и прочие детали
   реализации в `CONTEXT.md` не попадают.

5. ADR агент предлагает только для решений «трудно обратить + удивительно без
   контекста + реальный trade-off». Кандидат — язык интерфейса (смена позже трогает
   каждую страницу). Заглушка `/booking` и маршрут легко обратимы — ADR не нужны.
   Ожидаемая запись `docs/adr/0001-ui-language.md` (образец по ADR-FORMAT.md):

   ```markdown
   # Язык интерфейса — русский

   Интерфейс всего приложения на русском: аудитория проекта — русскоязычные
   пользователи. Интернационализация (i18n) сознательно вне объёма проекта;
   английские тексты скаффолда заменяются по мере переписывания страниц.
   ```

6. Вычитка артефактов по ходу и после интервью: термины совпадают со словами,
   которыми пользователь отвечал в интервью; в `CONTEXT.md` нет деталей реализации;
   ADR объясняет «почему», а не пересказывает «что».
