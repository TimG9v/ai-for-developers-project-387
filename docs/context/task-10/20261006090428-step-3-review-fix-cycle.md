  шага 1); правки в ветку PR делает агент

Исходный план: `20261006090428-implementation-plan.md`.

## Цель

В PR агента оставлены оба вида замечаний — общий комментарий в
обсуждении и комментарий к строке в diff, оба с `/oc`-вызовом; оба
обработаны агентом в той же ветке (новые коммиты видны), оба прогона
`opencode` — `success`; на synchronize отработал `opencode-review` и
оставил свои замечания (требования 2–4, задачи 3–5 описания).

## Interfaces

- Consumes: открытый PR агента (шаг 1, ветка `opencode/*`);
  `opencode.yml` — уже слушает и `issue_comment`, и
  `pull_request_review_comment` (правки воркфлоу не нужны);
  `opencode-review.yml` в `main` (шаг 2).
- Produces: обновлённая ветка PR (коммиты правок агента) — вход шага 4
  (мерж); замечания авторевью — материал финального решения о мерже.

## Предусловия (real-run перед стартом)

- [ ] 1. PR агента открыт, CI зелёный:

  ```bash
  gh pr list --state open
  gh pr checks <N>
  ```

  Ожидание: PR из `opencode/*`; проверки зелёные.

- [ ] 2. Авторевью в `main` (шаг 2):

  ```bash
  gh workflow list | grep review
  ```

  Ожидание: `opencode-review … active`.

- [ ] 3. Сформулировать два реальных замечания по фактическому diff
  (формулирует человек, читая PR): одно «общее» — про полноту/тесты/
  архитектуру, одно «точечное» — про конкретную строку кода. Примеры
  ниже в действиях 1 и 3 — подменить на фактические.

## Действия

- [ ] 1. Общий комментарий в обсуждении PR (кнопка Comment; текст
  с `/oc`; пример — заменить на фактическое замечание):

  ```text
  /oc Добавь юнит-тесты на освобождение слота после отмены записи —
  в постановке issue это критерий приёмки: слот снова появляется
  в /slots.
  ```

  Канал: событие `issue_comment` (PR технически issue) — существующий
  `opencode.yml` реагирует без правок.

- [ ] 2. Дождаться прогона и пуша:

  ```bash
  gh run list --workflow opencode --limit 3
  gh pr view <N> --json commits -q '.commits[].messageHeadline'
  ```

  Ожидание: прогон event `issue_comment` — `success`; в ветке PR
  появился коммит правки.

  **Важно:** не оставлять строчный комментарий, пока этот прогон не
  завершился, — два параллельных прогона пушат в одну ветку (риск
  отказа пуша/конфликта, review focus 3 плана).

- [ ] 3. Строчный комментарий: PR → Files changed → клик по номеру
  строки в конкретном файле → текст с `/oc` (пример — заменить на
  фактическое):

  ```text
  /oc Здесь при отсутствии записи нужен 404, а не пустой ответ —
  в постановке: несуществующий id записи — 404, UI не ломается.
  ```

  Канал: событие `pull_request_review_comment` — тот же
  `opencode.yml`, второй триггер. Агент получает файл, строки и
  diff-контекст из позиции комментария (docs) — путь и номер строки
  в тексте не дублировать.

- [ ] 4. Дождаться второго прогона и пуша:

  ```bash
  gh run list --workflow opencode --limit 4
  gh pr view <N> --json commits -q '.commits[].messageHeadline'
  ```

  Ожидание: прогон event `pull_request_review_comment` — `success`;
  ещё один коммит правки в той же ветке.

- [ ] 5. Проверить учёт обоих замечаний (задача 4 описания):

  ```bash
  gh pr diff <N> --name-only
  gh pr diff <N> | grep -A 3 "<фрагмент из замечания 1>"
  gh pr diff <N> | grep -A 3 "<фрагмент из замечания 2>"
  ```

  Ожидание: дифф закрывает и общее (тесты), и точечное (404)
  замечание; сверять с текстами комментариев из действий 1 и 3.

- [ ] 6. synchronize-авторевью (требование 4): после каждого пуша
  агента в ветку PR запускался `opencode-review`:

  ```bash
  gh run list --workflow opencode-review --limit 3
  ```

  Ожидание: прогоны event `synchronize` — `success`; замечания/резюме
  от `github-actions[bot]` в PR. Содержание прочитать: существенные
  замечания авторевью → вернуться к действию 1 (ещё один общий
  `/oc`-цикл); мелкие — учесть в решении о мерже (шаг 4).

- [ ] 7. Финальный CI на PR:

  ```bash
  gh pr checks <N>
  ```

  Ожидание: все проверки зелёные. Ветка PR готова к шагу 4.

## Результат шага (description.md)

Оба вида замечаний оставлены и обработаны агентом в той же ветке,
видно по коммитам; авторевью отработало на обновление PR. Замечания
авторевью прочитаны человеком (задачи 3–5 описания, требования 2–4).
