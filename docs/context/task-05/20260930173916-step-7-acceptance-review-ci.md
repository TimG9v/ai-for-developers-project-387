## Действия

1. Ревью всей ветки одним проходом (замечания «от вас нужно проверить… и
   вернуть замечания» — `descripton.md`): `/code-review` для диффа
   `main…task-5` по двум осям — Standards (правила репо: AGENTS.md, ADR,
   словарь `CONTEXT.md`) и Spec (спека #13: пути, методы, поля, коды ответов;
   швы; границы Out of Scope). Особые фокусы — Review Focus общего плана:
   правила на сервере, SDK без рукописного fetch, нет ручных правок
   сгенерированного, ключ уникальности по слоту.
2. Разобрать замечания: исправления — отдельными коммитами (Conventional
   Commits), каждый с зелёным `make test && make lint`. Замечание не
   «починено в тесте» — если падает тест, причина в коде фичи, не в тесте.
3. Приёмочный чек-лист (требования `descripton.md`, 7 пунктов) — пройтись
   по каждому с командой-доказательством (см. «Проверка»).
4. Открыть PR `task-5` → `main`:

   ```bash
   git push -u origin task-5
   gh pr create --base main --head task-5 \
     --title "feat: реализация бронирования (тикиеты #14–#18)" \
     --body-file /tmp/opencode/task-5-pr-body.md
   ```

   Тело PR: сводка пяти вертикалей, ссылка на спеку #13, отчёт e2e-прогона
   B1–B9, приёмочный чек-лист.
5. Дождаться GitHub Actions на PR (`gh pr checks --watch`); красный прогон —
   разбор по логам, исправление, повторный пуш. «Зелёный» — требование
   `descripton.md`, не опция.
6. Трекер: спека #13 остаётся открытой до мержа; после мержа — закрыть #13 и
   карту #12 (открытый вопрос 4 общего плана), проверив, что ни один тикет
   #14–#18 не остался открытым.
7. Контексты шага: перенести файлы `context/tmp/task-5/` (этот план, шаги,
   отчёты сессий) в `context/docs/task-5/` — по образцу task-4 (папка
   `context/tmp` в `.gitignore`, `context/docs` коммитится).
8. Мерж PR — по правилам finishing-a-development-branch (решение пользователя:
   merge/squash); release-please подберёт `feat:` в changelog.
