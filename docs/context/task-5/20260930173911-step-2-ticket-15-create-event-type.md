## Решение сессии: 400-ответ в контракте (см. «Точка внимания» общего плана)

Тикет требует серверного отклонения невалидного ввода, но контракт 400 не
моделирует (real-run: в `openapi/openapi.yaml` только 404/409 у `POST
/bookings`). Если сессия решает возвращать типизированный 400 — порядок
жёсткий:

1. Правка `contracts/main.tsp`: добавить модель ошибки, например

   ```tsp
   @doc("Невалидный ввод: обязательные поля пусты или значения вне допустимых границ.")
   model ValidationError {
     @statusCode statusCode: 400;
   }
   ```

   и присоединить её к ответам create-операций, которым нужна валидация
   (`EventTypes.create`, далее в #16/#17 — `Slots.create`, `Bookings.create`).
2. `make generate` (exit 0; `git status` показывает обновлённые `openapi/**`,
   `frontend/src/client/**`, серверные типы).
3. Только потом код обеих сторон и тесты.

Альтернатива без правки контракта (если пользователь отвергает 400 в спеке) —
обсудить в issue #15 до кода; самовольно опускать серверную валидацию нельзя
(acceptance-критерий тикета).

## Действия

1. Пользователь запускает `/implement` с тикетом: «реализуй #15 из спеки #13».
2. TDD на швах:
   - **Backend:** failing-тест — `POST /event-types` с валидным телом →
     успешный ответ и тип появляется в `GET /event-types`; невалидные тела
     (пустой `title`, `title` из пробелов, `durationMinutes: 0` и
     отрицательное, отсутствие полей) → отклонение (код — по решению сессии,
     см. выше). Валидация на сервере обязательна — форма её не заменяет.
   - **Frontend:** failing-тест страницы `/admin` — форма (название, описание,
     длительность), сабмит вызывает `eventTypesCreate()` из SDK (мок), после
     успеха тип виден в списке; клиентская валидация обязательных полей
     (пустое название/длительность — сабмит заблокирован с сообщением на
     русском). Никакого рукописного `fetch`.
3. Красный → зелёный; typecheck и точечные тесты по ходу; в конце
   `make test && make lint` — exit 0; `/code-review` внутри `/implement`.
4. Проверка результата, замечания в issue #15, исправления в той же сессии.
5. Закрыть тикет:

   ```bash
   gh issue close 15 --comment "реализовано: <коммиты>, тесты обоих швов зелёные"
   ```
