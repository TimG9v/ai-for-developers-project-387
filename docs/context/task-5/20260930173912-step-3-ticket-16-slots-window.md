## Решения сессии

1. **Окно 14 дней — константа на сервере** (решение карты; Out of Scope спеки:
   настраиваемое окно). Граница: слот, начинающийся в 14-й день, — валиден;
   15-й и позже — отклонение; в прошлом — отклонение (e2e B6).
2. **Форма 400** — как в шаге 2: если нужен типизированный 400 для
   `Slots.create` (слот вне окна, `endDateTime <= startDateTime`, тип не задан)
   — сначала правка `contracts/main.tsp` → `make generate` → код обеих сторон.
3. **`GET /slots` для гостя — только свободные слоты в окне.** На этом тикете
   записей ещё нет; с #17 фильтр «без занятых» обязан работать (acceptance
   #17: занятые слоты недоступны в календаре). Рекомендация: сразу возвращать
   свободные (не занятые) слоты в окне; владелец видит свои слоты через тот же
   эндпоинт или админку — в объём тикета не входит.

## Действия

1. Пользователь запускает `/implement` с тикетом: «реализуй #16 из спеки #13».
2. TDD на швах:
   - **Backend:** failing-тесты — `POST /slots` (валидный слот на завтра →
     успех; `eventTypeId` несуществующий → 404; `startDateTime` в 14-й день →
     успех; в 15-й день → отклонение; в прошлом → отклонение;
     `endDateTime <= startDateTime` → отклонение); `GET /slots?eventTypeId=…`
     — фильтр по типу, только окно (14-й день виден, 15-й нет). Сервер
     отсекает окно — клиент не источник правила.
   - **Frontend:** failing-тесты — владелец в `/admin` публикует слот (выбор
     типа, дата, время; сабмит → `slotsCreate()`, мок SDK); гость в `/booking`
     выбирает тип → видит слоты этого типа (`slotsList({ query: { eventTypeId
     } })`, мок), слоты вне окна не отображаются; интервал слота показывается
     с учётом длительности типа. Русский UI.
3. Красный → зелёный; `make test && make lint` в конце — exit 0; `/code-review`
   внутри `/implement`; замечания — в issue #16.
4. Закрыть тикет:

   ```bash
   gh issue close 16 --comment "реализовано: <коммиты>, тесты обоих швов зелёные"
   ```
