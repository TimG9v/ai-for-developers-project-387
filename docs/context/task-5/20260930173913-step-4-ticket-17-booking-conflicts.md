## Граница правила (зафиксировать в тестах, не изобретать лишнего)

- Уникальность — по `slotId`: одна Запись на Слот (решение карты #5); «409
  независимо от типа встречи» означает, что проверка не зависит от типа, к
  которому привязан слот. Прямой запрос в API вторую запись на тот же слот не
  создаст — это и проверяем.
- Пересечение интервалов у разных слотов (даже одного времени, разных типов)
  конфликтом не считается — правила на пересечение по времени в решениях карты
  нет; в объём не входит.
- Запись возможна только на слот в окне 14 дней: `GET /slots` уже не отдаёт
  вне окна, но `POST /bookings` прямым запросом обязан отклонять слот вне окна
  (история 16 спеки: правило единое для всех) — тест на HTTP-шве.
- Ошибки уже смоделированы контрактом для `Bookings.create`: 409
  `ConflictError`, 404 `NotFoundError` (`BookingsCreateErrors` в SDK). Для
  400 (пустое имя/email, слот вне окна) — как в шагах 2–3: правка контракта →
  `make generate` → код, если сессия вводит типизированный 400 (e2e B7 ждёт
  «API 400»).

## Действия

1. Пользователь запускает `/implement` с тикетом: «реализуй #17 из спеки #13».
2. TDD на швах:
   - **Backend:** failing-тесты — `POST /bookings` (валидная запись на
     свободный слот → успех; повторная на тот же слот → 409; несуществующий
     `slotId` → 404; пустые/отсутствующие `guestName`/`guestEmail` →
     отклонение; слот вне окна → отклонение). Атомарность в in-memory
     хранилище: проверка занятости и вставка — единая операция под блокировкой
     (insert-if-absent), а не «проверил, потом вставил» — иначе гонка двух
     одновременных запросов создаст вторую запись. После успеха слот исчезает
     из `GET /slots`.
   - **Frontend:** failing-тесты — выбор слота в календаре → форма записи
     (имя, email; валидация обязательности в форме, сообщения на русском);
     сабмит → `bookingsCreate()` (мок SDK); успех → экран подтверждения
     (история 10); ответ 409 → понятное сообщение занятости, предложение
     выбрать другое время (история 11); 404 → сообщение об устаревшей ссылке
     (история 12); занятые слоты в календаре недоступны для выбора — берутся
     из `GET /slots` (после бекенд-части возвращаются только свободные).
3. Красный → зелёный; `make test && make lint` в конце — exit 0;
   `/code-review` внутри `/implement`; замечания — в issue #17.
4. Закрыть тикет:

   ```bash
   gh issue close 17 --comment "реализовано: <коммиты>, тесты обоих швов зелёные"
   ```
