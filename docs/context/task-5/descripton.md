Реализация
Тикеты готовы, дальше их надо реализовать. Вызовите /implement и передайте ему тикеты.

Тикеты это граф с зависимостями. В любой момент есть фронтир: тикеты, у которых все блокирующие закрыты. Брать в работу можно любой из них.

Отдельно вызывать тесты и ревью не нужно, /implement делает это сам: пишет тесты на границах, которые зафиксированы в спецификации на прошлом шаге, прогоняет типы и тесты по ходу работы, а в конце проходит ревью и коммитит результат. От вас нужно проверить, что получилось, и вернуть замечания.

Основной сценарий бронирования проверяется в браузере: гость выбирает тип встречи, открывает календарь, занимает свободный слот и видит подтверждение, а владелец видит эту встречу в своём списке. Рекомендуем Playwright.

Правила бронирования должны выполняться на сервере. Проверка занятости только в интерфейсе обходится любым другим клиентом: прямой запрос в API создаст вторую запись на то же время.

Обращения к API идут через сгенерированный на прошлом шаге клиентский SDK. Руками написанный вызов fetch рядом с готовым клиентом уводит фронтенд от контракта, и расхождение всплывает уже на живом приложении. Если контракт по ходу работы меняется, порядок такой: правка TypeSpec, генерация, затем код обеих сторон.

Требования
Сквозной сценарий гостя проходится целиком: выбор типа встречи, календарь, запись на свободный слот, подтверждение.
Занятый слот не предлагается как свободный, повторная запись на это время не проходит, в том числе для другого типа встречи.
Правила бронирования выполняются на сервере.
Есть страница владельца со списком предстоящих встреч всех типов.
Реализация совпадает с контрактом: пути, методы, имена полей, коды ответов.
Фронтенд обращается к API через сгенерированный клиентский SDK.
Тесты покрывают основной сценарий бронирования и конфликт слотов, прогон в GitHub Actions зелёный.
Ссылки
Playwright MCP: запуск браузерных сценариев и автоматизация пользовательских действий через агента.
Chrome Devtools MCP: диагностика проблем в браузере, включая сеть, консоль и состояние страницы.
Задачи
Вызовите /implement и реализуйте тикеты, начиная с тех, у которых нет блокирующих.
Проверьте сквозной сценарий бронирования в браузере.
Разберите замечания ревью и убедитесь, что прогон в GitHub Actions зелёный.
Результат шага
Приложение работает по контракту, основной сценарий бронирования проходится и покрыт тестами.
