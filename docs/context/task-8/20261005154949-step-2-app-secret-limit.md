# step-2-app-secret-limit

- Дата: 2026-10-05 15:49
- Ветка: `main` (после мержа шага 1); коммитов шаг не даёт
- Шаг: план шага 2/3 — GitHub App, секрет `OPENCODE_API_KEY`, лимит расходов

Исходный план: `20261005154949-implementation-plan.md`.

## Цель

App «opencode-agent» установлен на репозиторий, секрет `OPENCODE_API_KEY`
существует в GitHub Secrets, лимит расходов в кабинете провайдера
проверен/выставлен; значение ключа не попадает ни в файлы репозитория,
ни в чат и логи.

## Interfaces

- Consumes: воркфлоу в `main` с именем секрета `OPENCODE_API_KEY` (шаг 1).
- Produces: работающая связка «App + секрет» — предусловие живого вызова
  шага 3; факт «установка App подтверждена пользователем» и факт «секрет
  существует, обновлён <дата>».

## Распределение ролей

| Действие                | Кто                                       | Почему                                                                    |
| ----------------------- | ----------------------------------------- | ------------------------------------------------------------------------- |
| Установка GitHub App    | пользователь (браузер)                    | OAuth-установка приложения в аккаунт/репозиторий через CLI невозможна     |
| Создание секрета        | пользователь (`gh secret set` или web-UI) | значение ключа не должно проходить через агента, чат и логи               |
| Лимит расходов          | пользователь (консоль opencode)           | личный кабинет, доступов у агента нет                                     |
| Верификация результатов | агент (`gh`)                              | имя и дата секрета видны без значения; остальное — по косвенным признакам |

- [ ] 2. Секрета ещё нет:


  Ожидание: только `HEXLET_ID` (real-run 2026-10-05).

## Действия пользователя

- [ ] 1. Установить App: открыть <https://github.com/apps/opencode-agent>
  → Configure/Install → выбрать `TimG9v` → только
  `ai-for-developers-project-387` (All repositories не нужно). Проверить
  установку: GitHub → Settings → Integrations → Applications → Installed
  GitHub Apps → `opencode-agent` → Repository access содержит репозиторий.

- [ ] 2. Получить ключ: у студента программы «ИИ для разработчиков» ключ
  для GitHub Actions выдаёт куратор (написать ему; вкладки API Keys в
  пространстве Hexlet Students у студента нет). Альтернатива — ключ
  личного пространства из <https://opencode.ai/console> → API Keys
  (значение показывается один раз — сразу переходить к вводу).

- [ ] 3. Положить ключ в секрет (вариант CLI, значение вводится
  интерактивно и в историю терминала не попадает):

  ```bash
  gh secret set OPENCODE_API_KEY --repo TimG9v/ai-for-developers-project-387
  # в терминале появится подсказка "? Paste your secret:" — вставить значение, Enter
  ```

  Вариант web-UI: репозиторий → Settings → Secrets and variables →
  Actions → New repository secret → Name: `OPENCODE_API_KEY`, Secret:
  <значение>. Имя секрета должно совпасть байт-в-байт с `env:` воркфлоу.
  Ключ в чат, файлы, скриншоты и комментарии не вставлять.

- [ ] 4. Лимит расходов: в <https://opencode.ai/console> — для Hexlet
  Students проверить Overview (лимит $20 программы: $15/мес терминал +
  остаток на ключе Actions, вкладка Logs — расход по запросам); для
  личного пространства выставить monthly usage limit (Settings/Limits) и
  при необходимости отключить auto-reload.

## Действия агента (верификация)

- [ ] 1. Секрет существует (значение недоступно по API — проверяется факт):

  ```bash
  gh secret list
  ```

  Ожидание: `OPENCODE_API_KEY` с датой обновления текущего запуска.

- [ ] 2. Значения ключа нет в файлах репозитория (по маскам значения;
  ищем и имя переменной вне воркфлоу, и обрывки настоящих ключей):

  ```bash
  git grep -n "OPENCODE_API_KEY" -- . ':!.github/workflows/opencode.yml' ; echo "exit=$?"
  git grep -nE "sk-[A-Za-z0-9]{8,}|oc-[A-Za-z0-9]{8,}" -- . ; echo "exit=$?"
  ```

  Ожидание: обе команды — «not found», exit 1 (grep без совпадений).

- [ ] 3. Имя секрета в воркфлоу совпадает с созданным:

  ```bash
  git grep -n "secrets.OPENCODE_API_KEY" -- .github/workflows/opencode.yml
  ```

  Ожидание: одно вхождение в `env:` шага «Run OpenCode».

- [ ] 4. Результаты действий пользователя (установка App, лимит) принять
  по подтверждению пользователя и зафиксировать в отчёте шага; прямых
  CLI-проверок нет (real-run 2026-10-05: REST отвечает 403 без app-токена).
  Косвенное доказательство установки App — успешный прогон шага 3.

Шаг без коммитов: секрет живёт в настройках репозитория, дерево не
меняется. Артефакт шага — заполненная таблица «Проверка» и подтверждение
пользователя.

## Предусловия следующих шагов

Шаг 3 требует от шага 2: установленный App, существующий непустой
`OPENCODE_API_KEY`. Пустой или отсутствующий секрет роняет шаг агента на
аутентификации (справка Хекслета) — вызывать агента до зелёной таблицы
этого шага нельзя.
