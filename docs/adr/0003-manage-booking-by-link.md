# Управление записью по ссылке с id без авторизации

Отменять и переносить запись гость и владелец могут без логина: идентификатор
записи генерирует клиент (`crypto.randomUUID()`) и отдаёт гостю в
подтверждении как ссылку `/booking/manage?id=<id>`; guessing id практически
невозможен, поэтому он работает как unguessable-токен. Это продолжение
решения «Owner-API без проверки доступа» (ADR 0002): роль владельца
поддерживается только маршрутом админки в UI, операции отмены/переноса — те
же контрактные `DELETE /bookings/{id}` и `POST /bookings/{id}/reschedule` и
для гостя, и для владельца. Когда появится авторизация, проверка добавится
на этих же эндпоинтах, а ссылка управления останется способом найти запись
без входа.

Следствие: email-уведомлений в сервисе нет, поэтому ссылку нужно сохранить
сразу после записи — другого способа найти свою запись у гостя нет.
